# 린 캔버스: 재고 부족 자동 재주문 커머스 웹 MVP

> 작성 기준: [docs/PRD.md](./PRD.md)
> ※ 아래 1~9번은 Running Lean에서 제시하는 작성 순서이며, 실제 작성 순서는 제품/서비스에 따라 임의로 조정할 수 있다.

## 1. 문제 (Problem)

- 소규모 셀러는 재고 관리 인력이 없어 특정 상품의 재고가 임계치 이하로 떨어져도 이를 놓치고 품절 상태로 주문을 받는다.
- 재고 소진 사실을 뒤늦게 인지해 발주가 늦어지고, 그 사이 판매 기회를 잃거나 고객에게 품절 안내/환불을 해야 하는 상황이 발생한다.
- 재고·발주 현황을 수기 혹은 별도 스프레드시트로 관리해 실시간 주문 상황과 괴리가 생기고, 관리 부담이 크다.

## 2. 고객 세그먼트 (Customer Segments)

- **주 고객(관리자)**: 재고 관리 전담 인력 없이 1~2인이 직접 운영하는 소규모 온라인 셀러
- **일반 사용자(고객)**: 해당 쇼핑몰에서 상품을 검색·구매하는 일반 소비자
- **얼리어답터**: 이미 온라인으로 소량 상품을 판매 중이며, 품절/재고 관리 실패를 겪어본 1인 셀러

## 3. 가치 제안 (Unique Value Proposition)

재고가 임계치 이하로 떨어지면 시스템이 자동으로 발주 요청을 생성해, 셀러가 별도로 재고를 확인하지 않아도 품절 없이 판매를 지속할 수 있는 재고 자동화 커머스 플랫폼

- 상위 개념: "재고 걱정 없는 1인 쇼핑몰"
- 결제 → 재고 차감 → 임계치 체크 → 발주 요청 생성까지 하나의 트랜잭션으로 자동 처리

## 4. 해결책 (Solution)

- 결제 승인 시점에 재고 차감과 임계치 체크를 서버 트랜잭션(`process_order_payment`)으로 원자적 처리
- 임계치 미만 시 관리자 발주관리 페이지에 발주 요청을 자동 생성(중복 발주 방지 로직 포함)
- 관리자 대시보드에서 매출/주문 건수/재고부족 상품 현황을 한눈에 요약 제공
- 발주 요청을 pending → confirmed → received 단계로 관리하며, 입고 처리 시 재고 수량 자동 반영

## 5. 채널 (Channels)

- 웹 브라우저(모바일/데스크톱 반응형 웹) 직접 접속
- 향후 소규모 셀러 커뮤니티/카페, 검색 유입(SEO)을 통한 신규 셀러 확보(MVP 이후)

## 6. 수익 흐름 (Revenue Streams)

- 상품 판매 매출(토스페이먼츠를 통한 결제 승인 기반)
- (MVP 이후 확장 가능) 셀러 대상 SaaS 구독료 또는 거래 수수료 모델

## 7. 비용 구조 (Cost Structure)

- 앱/서비스 개발 및 유지보수 인건비
- Supabase(DB, 인증) 및 서버 인프라 운영비
- 토스페이먼츠 결제 수수료
- 도메인/호스팅 비용

## 8. 핵심 지표 (Key Metrics)

- 자동 발주 요청 생성 건수 및 발주 확인→입고 소요 시간
- 재고 임계치 미만 상태로 방치된 상품 수(대시보드 노출 기준)
- 결제 완료 주문 건수 및 총 주문 금액
- 신규 가입 셀러 수, 신규 가입 고객 수

## 9. 경쟁 우위 (Unfair Advantage)

- 결제 승인–재고 차감–자동 발주를 단일 트랜잭션으로 묶어 재고 불일치·중복 발주 위험을 원천 차단하는 구조
- 별도의 재고관리 툴이나 스프레드시트 연동 없이, 쇼핑몰 자체에 발주 자동화가 내장되어 있어 소규모 셀러가 추가 도구를 학습/연동할 필요가 없음
